# 没有公网 IP，也能随时回家：群晖 NAS 装 Tailscale 保姆级实录

欢迎登陆「屿华AI」数字岛屿。大家好，我是屿华。

上一篇聊了「NAS 当仓库、Mac 当机房」的存算分离架构，评论区问得最多的是：人在外面，怎么连回家里这套系统？

今天补上那座最关键的「桥」。照例先从一个真实场景说起。

## 一、外网访问 NAS，为什么这么难？

上周五下班，我还在地铁上，编辑在微信上催：那篇稿子改得怎么样了？

稿子在哪？在我家 NAS 的 Obsidian 写作库里。人在地下一层，NAS 在家里书架上——这就是所有 NAS 玩家的第一道坎：**怎么在外面访问家里的 NAS？**

传统路线，条条是坑：

- **申请公网 IPv4**：打运营商客服，大概率得到「您所在区域没有公网 IP 资源」的回复。就算要到了，80/443 端口也常年被封；
- **DDNS + 端口映射**：光猫改桥接、路由器配映射、域名绑动态 IP，每一环都是坑。更大的问题是把 NAS 端口直接暴露公网，等于家门口挂金库招牌；
- **群晖 QuickConnect**：零配置，但流量走群晖中转，速度看运气；
- **花生壳、SakuraFRP 等穿透服务**：免费版限速到 1Mbps 级别，还要实名认证，体验好的档位按年交钱。

**外网访问的门槛，从来不是 NAS 不行，而是「回家」这条路太难修。**

今天的主角 Tailscale，思路完全不同：不修路，让所有设备「本来就认识」。

## 二、Tailscale 是什么？一分钟看懂

一句话：基于 WireGuard 协议的异地组网工具，效果等同于把你的所有设备插在同一个路由器上。

原理用一个比喻讲清楚：

1. **总控室**：所有设备（NAS、Mac、手机）登录同一个 Tailscale 账号，在控制服务器上完成登记；
2. **专属门牌**：每台设备分到一个固定不变的虚拟 IP（100.x.x.x 开头）；
3. **私下接头**：设备间通信优先 P2P 直连（NAT 打洞），速度接近裸连；打洞失败才走官方中继，同样端到端加密，只是速度打折扣。

三个关键特性：

- **零端口暴露**：不需要公网 IP，不在路由器上开任何端口，扫描器根本看不见你；
- **智能分流**：默认只接管 100.x.x.x 网段流量，刷网页看视频照常走本地网络，不拖网速、不费手机电量；
- **全平台客户端**：群晖、Mac、Windows、Linux、iOS、Android 一个不缺。

**装完之后，全世界的设备都像插在同一个路由器上。**

## 三、为什么极客圈独宠它？一张表看懂

| 方案 | 上手难度 | 速度 | 安全性 | 成本 |
|---|---|---|---|---|
| 公网 IP + DDNS + 端口映射 | ⭐⭐⭐⭐ | 快 | 端口裸奔，风险高 | 域名费用 |
| QuickConnect | ⭐ | 慢，走中转 | 尚可 | 免费 |
| 花生壳等穿透服务 | ⭐⭐ | 免费版限速 | 中转方可见元数据 | 免费版鸡肋 |
| frp / SakuraFRP | ⭐⭐⭐⭐ | 看节点 | 需自备 VPS、实名 | VPS 租金 |
| **Tailscale** | **⭐** | **优先直连，接近裸速** | **WireGuard 端到端加密** | **个人版免费** |

表格外再补两点：

1. **免费额度大方**：个人版免费 100 台设备。我自己的网络里就挂着五台——NAS、MacBook、iPhone 和两台 Windows，离免费上限还远得很；
2. **不被锁定**：底层协议开源，未来可以自建兼容服务端（headscale）平滑迁走，数据主权在自己手里。

## 四、三步配置（ARM 群晖实测）

交代背景：我的 NAS 是 ARM 架构的入门款群晖，这类机器套件中心搜不到 Tailscale，也用不了 Docker。**唯一正确姿势是手动装官方 spk 包**。别慌，总共三步。

### 第一步：注册账号（2 分钟）

访问 Tailscale 官网（tailscale.com），点「Get Started」，用 Google、Microsoft 或 Apple 账号授权登录。

登录后进入 admin console 控制台，这就是管理所有设备的「总控室」，Machines 页面会列出每一台入网设备。

### 第二步：群晖手动安装（5 分钟）

1. 浏览器打开官方套件下载页：[pkgs.tailscale.com/stable/#spks](https://pkgs.tailscale.com/stable/#spks)；
2. 下载对应自己机型架构的安装包（不确定的，去群晖官网查自己型号的 CPU 架构：ARM 机选 armv8 包，Intel 机选 x86_64 包）；
3. 打开 DSM 桌面 →「套件中心」→ 右上角「手动安装」→ 上传这个 .spk 文件；
4. 弹出「此套件需要系统特权」的警告属正常现象，同意并完成安装；
5. 打开 Tailscale 套件，点登录，把弹出的授权 URL 复制到任意设备的浏览器里完成授权；
6. 回到 admin console 的 Machines 页面——你的群晖已经在线，旁边分到了一个 100.x.x.x 的固定 IP。

**装完先做两件事**（都在 admin console，都是血泪经验）：

- **关闭密钥过期**：Machines → 找到 NAS → Disable key expiry。默认密钥 90 天过期，到时候 NAS 悄悄掉线，而你人在外地干瞪眼——这是我替你踩过的坑；
- **开启 MagicDNS**：DNS 页 → Enable MagicDNS。以后直接用设备名当域名，连 IP 都不用背——访问 NAS 后台时，地址里那串 IP 换成它的设备名就行。

### 第三步：Mac 与 iPhone 入网（各 2 分钟）

- **Mac**：官网下载客户端，登录同一个账号，菜单栏常驻一个小图标；
- **iPhone**：App Store 搜 Tailscale，安装后允许添加 VPN 配置（这就是加密隧道的载体），开关保持 Active 即可。

**验收时刻**：Mac 连上手机热点，把浏览器里平时访问 DSM 的地址开头那串局域网 IP，换成 NAS 的 Tailscale IP（或设备名）——登录页秒开。

恭喜，从此地球上任何有网的地方，都是你家的客厅。

## 五、三个真实场景，感受「无感」二字

工具好不好，场景说了算。这三个都是我日常真实在用的。

### 场景一：地铁上审稿，知识库随身带

回到开头编辑催稿那一幕。手机打开 Obsidian，Remotely Save 插件的服务器地址只需小改一处：把平时局域网访问群晖 WebDAV 的地址里的 IP，换成 NAS 的 Tailscale 设备名，端口照旧——走加密隧道，几百篇笔记几秒同步完，批注当场写完回传。

**你现在看到的这篇推文，初稿就是这么在通勤路上过完的。**

### 场景二：出差途中，DSM 后台随身管

酒店 WiFi 连上 MacBook，浏览器里 DSM 的地址换个开头，直接进 NAS 后台：看一眼硬盘健康度，顺手丢一个下载任务——晚上到家，片子已经躺在盘里。

### 场景三：通勤路上，无损曲库揣兜里

手机上的 Subsonic 协议播放器，直连 NAS 里的 Navidrome 音乐服务器（上篇介绍过的那个），家里整套无损专辑变成随身听。流量紧张？出门前在家里 WiFi 同步几张专辑离线。

三个场景，对应三类典型服务：**文件同步、Web 后台、流媒体**。先想清楚自己在外网要访问什么，再决定把什么服务放在哪台设备上——这是比任何工具都重要的架构思维。

## 屿华的极客小结

1. **换思路**：外网访问的最优解不是修路（公网 IP），而是让所有设备「本来就认识」（Tailscale）；
2. **ARM 群晖别慌**：手动装官方 spk 五分钟搞定，装完第一件事关掉密钥过期；
3. **MagicDNS 是隐藏福利**：设备名当域名，IP 都不用背；
4. **场景先于工具**：先想清楚在外面要访问什么，再决定服务放哪台设备。

不需要公网 IP，不花一分钱，一条加密隧道把所有设备紧紧连在一起——「外网访问焦虑症」，今天彻底治愈。
