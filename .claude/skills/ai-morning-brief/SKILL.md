# AI 早报（工作日早间图文）

> **状态：2026-11-16 搁置（创刊号成稿前被毙）**——多事件杂烩没有单一钩子，小号无阅读习惯红利，事实占比过高违背「事实是 commodity」原则，与市面无人看的 AI 速报同构。雷达方法论（24h 时间窗 + 中文查重）保留，用于给「单点深拆长文」找选题（见 ai-weekly 同日封存注记）。若解封需先回答「单篇钩子是什么」。

每天早 7:30 公众号发一篇短图文：**当天 1~5 个 AI 事件**（平淡日少讲、讲透；大新闻日多列几条、每条短一点），每个事件「事实 2 句 + 工程师锐评 2 句」。差异化只有一条：**别人转述，我们讲对干活的人意味着什么**——转述一句都不要写。

- 目录：`drafts/ai-morning-brief/<期号=发布日YYYYMMDD>/article.md`，`collection: AI 早报`，`platform: [公众号]`（试运行期只发公众号，不碰知乎/CSDN）
- 配图：仅 1 张封面（img-src/ 手写 SVG → render-img.js），正文不配图，生产成本压到最低
- 事件窗口：过去 24h 为主；仍在发酵的大事（有新进展）可带，但必须提最新进展，不炒冷饭

## 每期流程

### ① 雷达（复用 ai-weekly 方法论，窗口改 24h）

HN Algolia：`curl -s "https://hn.algolia.com/api/v1/search?tags=story&numericFilters=created_at_i>{24h前unix},points>40&hitsPerPage=20"` + 关键词补漏（OpenAI/Anthropic/Gemini/Nvidia/agent）+ WebSearch「AI news today」。热度数字以 API 为准。

### ② 选件（1~5 件，按当天密度）

- 件数规则：硬货多的大新闻日 4~5 件（每条锐评可压缩到 1 句）；平淡日 1~2 件，讲透比讲多强；没硬货就明说「今天没大事」并挑一件次热的展开——凑数消耗信任
- 多样性：多件时尽量跨领域（大模型/硬件/agent/安全隐私/开源），同一家公司最多 1 件
- 中文查重：搜中文关键词，已刷屏的事件降低优先级（读者已知 = 无增量），优先「热度高 + 中文空白」

### ③ 成稿（模板）

```
开场 2~3 行：今天定调一句话（与当天最大事件呼应），创刊期加一句栏目自介
（每个事件：）
## N. 一句话事件标题（带热度/日期锚点）
事实 2 句：发生了什么（以原文为准，不凭印象）
工程师锐评 2 句：这对写代码/做产品/管算力的人意味着什么——这是正文的差异化本体
收尾 3 行内：互动（哪件想看深拆？评论区说）+ 固定一句栏目预告
```

- ~1000 字，短段落，结论前置；**不用感叹号，不堆情绪词**（沿用 writing-rules 红线）
- 事实必须核对原文（WebFetch 至少 1 个一手源/事件），指控性新闻用「被曝/据报道」

### ④ 封面与推送

封面 SVG（深蓝霓虹风：期号 + 日期 + 当天 3 行事件标题）→ `render-img.js` 出 cover.jpg → 用户终审 → `node .claude/skills/write-article/scripts/push-draft.js <文件夹>`（只有封面图，插图阶段自动跳过内文图）。发布人工：勾 AI 生成内容标识。

### ⑤ 每日记账 & 复盘

发布后把阅读数记进本 skill `references/metrics.md`（日期/标题/阅读/在看/新增关注）。**试运行框架：10 个工作日（2026-11-17 起）**，任一触发即停，回归每周 1~2 篇深拆主线：平均阅读 < GitHub 周榜一半；掉粉明显；关注转化趋零。
